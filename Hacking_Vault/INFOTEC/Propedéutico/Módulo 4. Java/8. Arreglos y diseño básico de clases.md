
# Arreglos y Diseño Básico de Clases en Java

## Arreglos en Java: una colección organizada de datos

Un **arreglo (Array)** es una estructura de datos que permite almacenar múltiples elementos del mismo tipo bajo un mismo nombre. Una forma sencilla de comprenderlo es imaginar un **archivero** con varios cajones numerados. El archivero representa el arreglo, mientras que cada cajón representa una posición donde se almacena un dato. Cada posición posee un índice que comienza en **0**, por lo que el primer elemento siempre se encuentra en la posición cero.

Los arreglos tienen una característica importante: **su tamaño es fijo**. Una vez creado un arreglo con una determinada cantidad de elementos, ese tamaño no puede modificarse durante la ejecución del programa. Si posteriormente se requiere almacenar más información, será necesario crear un nuevo arreglo o utilizar estructuras dinámicas como `ArrayList`.

La representación conceptual de un arreglo puede visualizarse de la siguiente manera:

```text
Índice      0      1      2      3      4
          ┌────┬────┬────┬────┬────┐
Arreglo   │Ana │Luis│Sofía│Juan│Eva │
          └────┴────┴────┴────┴────┘
```

Para declarar un arreglo se debe indicar el tipo de dato que almacenará y posteriormente su tamaño.

```java
int[] edades = new int[5];
```

También es posible inicializarlo directamente con valores.

```java
int[] edades = {20, 18, 25, 30, 27};
```

En el caso de arreglos de texto:

```java
String[] nombres = {"Ana", "Luis", "Pedro", "María"};
```

Cada elemento puede consultarse mediante su índice.

```java
System.out.println(nombres[2]);
```

Salida:

```text
Pedro
```

# Características de los arreglos

Los arreglos presentan diversas características que es importante conocer antes de utilizarlos.

|Característica|Descripción|
|---|---|
|Homogéneos|Todos los elementos deben ser del mismo tipo de dato.|
|Tamaño fijo|No puede modificarse después de su creación.|
|Índices|Comienzan siempre en cero.|
|Acceso rápido|Permiten acceder directamente a cualquier posición mediante su índice.|
|Memoria continua|Sus elementos se almacenan de forma contigua en memoria, mejorando el rendimiento.|

# De un objeto real a una clase en Java

La Programación Orientada a Objetos busca representar objetos del mundo real mediante clases.

Por ejemplo, pensemos en un automóvil. Un automóvil posee características como color, marca, modelo y velocidad. Además, puede realizar acciones como acelerar, frenar o encender.

En Java se representa de la siguiente manera:

```java
public class Automovil {

    String marca;
    String color;
    int velocidad;

    public void acelerar() {
        velocidad += 10;
    }

    public void frenar() {
        velocidad -= 10;
    }

}
```

Una vez definida la clase, pueden crearse distintos objetos.

```java
Automovil auto1 = new Automovil();
Automovil auto2 = new Automovil();
```

Cada objeto posee sus propios valores, aunque ambos fueron creados a partir de la misma clase.

# Arreglo vs Clase en Java

Es común que los estudiantes confundan estos dos conceptos. Sin embargo, cumplen funciones completamente diferentes.

Un arreglo sirve para almacenar múltiples datos del mismo tipo, mientras que una clase sirve para modelar objetos con atributos y comportamientos.

|Arreglo|Clase|
|---|---|
|Almacena varios elementos.|Modela objetos reales.|
|Todos los datos son del mismo tipo.|Puede contener diferentes tipos de datos.|
|Tiene longitud fija.|Puede crear tantos objetos como sea necesario.|
|No contiene comportamiento.|Contiene atributos y métodos.|
|Se accede mediante índices.|Se accede mediante objetos.|

Por ejemplo, un arreglo de nombres almacena únicamente cadenas de texto.

```java
String[] nombres = {"Ana", "Luis", "Pedro"};
```

Mientras que una clase Persona puede almacenar múltiples características.

```java
public class Persona{

    String nombre;
    int edad;
    double estatura;

}
```

Posteriormente puede existir un arreglo de objetos.

```java
Persona[] alumnos = new Persona[30];
```

En este caso el arreglo almacena objetos de tipo Persona y no datos simples.

# Ciclos para recorrer arreglos

La mayoría de las operaciones sobre arreglos consisten en recorrer cada uno de sus elementos utilizando estructuras repetitivas.

El ciclo `for` es el más utilizado.

```java
String[] nombres = {"Ana","Luis","Pedro","María"};

for(int i=0; i<nombres.length; i++){

    System.out.println(nombres[i]);

}
```

La propiedad `length` devuelve el tamaño del arreglo.

Existe una versión más sencilla denominada **for-each**, especialmente útil cuando únicamente se desea leer los elementos.

```java
for(String nombre : nombres){

    System.out.println(nombre);

}
```

La diferencia entre ambos ciclos puede resumirse en la siguiente tabla.

|for tradicional|for-each|
|---|---|
|Permite conocer el índice.|No proporciona el índice directamente.|
|Puede modificar posiciones específicas.|Generalmente se utiliza para lectura.|
|Es más flexible.|Su sintaxis es más sencilla.|

# ¿Qué es una clase?

Una **clase** es una plantilla o modelo que describe cómo serán los objetos que se crearán a partir de ella.

Una clase no representa un objeto específico, sino el plano para construir muchos objetos similares.

Por ejemplo:

```java
public class Estudiante{

}
```

Esta clase todavía no contiene información, pero servirá para crear múltiples estudiantes.

Cada objeto creado a partir de una clase recibe el nombre de **instancia**.

```java
Estudiante alumno1 = new Estudiante();
Estudiante alumno2 = new Estudiante();
```

# Atributos y métodos

Los **atributos** representan las características del objeto.

Los **métodos** representan las acciones que el objeto puede realizar.

Ejemplo:

```java
public class Persona{

    String nombre;
    int edad;

    public void saludar(){

        System.out.println("Hola");

    }

}
```

|Elemento|Función|
|---|---|
|nombre|Atributo|
|edad|Atributo|
|saludar()|Método|

En Programación Orientada a Objetos es recomendable que los atributos describan el estado del objeto, mientras que los métodos definan su comportamiento.

---

# Constructor

El constructor es un método especial que se ejecuta automáticamente cuando se crea un objeto.

Su función principal consiste en inicializar los atributos del objeto.

Ejemplo:

```java
public class Persona{

    String nombre;
    int edad;

    public Persona(String nombre, int edad){

        this.nombre = nombre;
        this.edad = edad;

    }

}
```

Al crear el objeto:

```java
Persona persona1 = new Persona("Raúl",25);
```

Los atributos quedan inicializados desde el momento de su creación.

Si una clase no define un constructor, Java crea automáticamente un **constructor vacío**.

# Modificadores de acceso

Los modificadores de acceso controlan desde dónde pueden utilizarse los atributos y métodos.

|Modificador|Acceso|
|---|---|
|public|Accesible desde cualquier clase.|
|private|Solo desde la misma clase.|
|protected|Desde la clase, subclases y mismo paquete.|
|(sin modificador)|Solo dentro del mismo paquete.|

Ejemplo:

```java
public class Persona{

    private String nombre;

    public void saludar(){

    }

}
```

La práctica recomendada consiste en declarar los atributos como **private** y acceder a ellos mediante métodos públicos.

# Paso de parámetros a métodos

Los métodos pueden recibir información mediante parámetros.

```java
public void saludar(String nombre){

    System.out.println("Hola " + nombre);

}
```

Llamada al método:

```java
saludar("Carlos");
```

También pueden recibir varios parámetros.

```java
public int sumar(int a, int b){

    return a + b;

}
```

Uso:

```java
int resultado = sumar(5,8);
```

Los parámetros permiten reutilizar un mismo método con distintos valores de entrada.

# Getters y Setters

Los métodos **Getter** y **Setter** permiten acceder a los atributos privados sin violar el principio de encapsulamiento.

El Getter obtiene el valor de un atributo.

```java
public String getNombre(){

    return nombre;

}
```

El Setter modifica el valor.

```java
public void setNombre(String nombre){

    this.nombre = nombre;

}
```

Su utilización sería:

```java
Persona persona = new Persona();

persona.setNombre("Ana");

System.out.println(persona.getNombre());
```

Este mecanismo protege los datos internos del objeto y permite validar la información antes de almacenarla.

---

# Llamada a métodos de objetos

Una vez creado un objeto, sus métodos se invocan utilizando el operador punto (`.`).

```java
Persona persona = new Persona("Luis",22);

persona.saludar();
```

También es posible acceder a los métodos Getter y Setter.

```java
persona.setNombre("Carlos");

String nombre = persona.getNombre();
```

La sintaxis general es:

```text
objeto.metodo();
```

o bien

```text
objeto.metodo(argumentos);
```

# Los cuatro pilares de la Programación Orientada a Objetos

La Programación Orientada a Objetos (POO) se basa en cuatro principios fundamentales que permiten desarrollar software modular, reutilizable y fácil de mantener.

|Pilar|Descripción|Ejemplo|
|---|---|---|
|Encapsulamiento|Protege los datos internos de un objeto mediante atributos privados y métodos públicos.|Uso de atributos `private` con Getters y Setters.|
|Abstracción|Oculta los detalles internos mostrando únicamente lo necesario para utilizar un objeto.|El usuario utiliza un método sin conocer su implementación.|
|Herencia|Permite que una clase herede atributos y métodos de otra.|`class Alumno extends Persona`.|
|Polimorfismo|Un mismo método puede comportarse de distintas maneras según el objeto que lo utilice.|Sobrescritura de métodos (`@Override`).|

## Encapsulamiento

El encapsulamiento consiste en ocultar los datos internos del objeto para evitar modificaciones no controladas. En lugar de acceder directamente a los atributos, se utilizan métodos públicos que permiten leer o modificar la información de forma segura.

## Abstracción

La abstracción permite concentrarse en las características esenciales de un objeto sin preocuparse por los detalles de su implementación. Por ejemplo, al utilizar el método `System.out.println()`, el programador no necesita conocer cómo Java envía realmente la información a la consola.

## Herencia

La herencia favorece la reutilización del código al permitir que una clase adquiera los atributos y métodos de otra. La clase que hereda se denomina **subclase** y la clase de la cual hereda se conoce como **superclase**.

```java
public class Persona{

    String nombre;

}

public class Alumno extends Persona{

    String matricula;

}
```

En este ejemplo, `Alumno` hereda automáticamente el atributo `nombre` de `Persona`.

## Polimorfismo

El polimorfismo permite que un mismo método tenga comportamientos diferentes dependiendo del objeto que lo implemente. Esto proporciona flexibilidad y facilita la extensión de los programas.

```java
class Animal{

    public void hacerSonido(){

        System.out.println("Sonido");

    }

}

class Perro extends Animal{

    @Override
    public void hacerSonido(){

        System.out.println("Ladrido");

    }

}
```

Aunque ambos objetos utilizan el método `hacerSonido()`, el resultado será distinto según el tipo de objeto que lo ejecute.

# Relación entre arreglos y clases

En aplicaciones reales es muy común utilizar arreglos para almacenar objetos creados a partir de una clase. Por ejemplo, un sistema escolar puede almacenar varios estudiantes dentro de un mismo arreglo.

```java
public class Estudiante{

    String nombre;
    int edad;

}

public class Principal{

    public static void main(String[] args){

        Estudiante[] grupo = new Estudiante[3];

        grupo[0] = new Estudiante();
        grupo[0].nombre = "Ana";
        grupo[0].edad = 20;

        grupo[1] = new Estudiante();
        grupo[1].nombre = "Luis";
        grupo[1].edad = 21;

        grupo[2] = new Estudiante();
        grupo[2].nombre = "María";
        grupo[2].edad = 19;

        for(Estudiante estudiante : grupo){

            System.out.println(estudiante.nombre + " - " + estudiante.edad);

        }

    }

}
```

Este ejemplo reúne varios de los conceptos estudiados: la definición de una clase, la creación de objetos mediante el operador `new`, el almacenamiento de dichos objetos en un arreglo y el recorrido del arreglo utilizando un ciclo `for-each`. En el desarrollo de aplicaciones orientadas a objetos, esta combinación es una de las más utilizadas, ya que permite organizar grandes cantidades de información de manera estructurada y facilita la implementación de programas escalables y fáciles de mantener.
