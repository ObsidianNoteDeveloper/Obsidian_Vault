
## Desventajas de un sistema distribuido


- Software en desarrollo
	- Gran parte del software para sistemas distribuidos está aun desarrollo.
	
- Problemas de transmisión en redes
	- los problemas de transmisión en las redes de comunicación todavía son frecuentes en la transferencia de datos, por ejemplo en archivos multimedia (latencia)
	
- Riesgos de seguridad
	- Se necesitan mejores esquemas de protección para mejorar el acceso a información confidencial o secreta (Análisis de grafos, Ciberseguridad, Criptografía, Seguridad en redes)
	
- Fallas operativas y de hardware
	- Debe haber tolerancia a fallas operativas y de componentes que son frecuentes

## Organizar una red de Computadoras

Existen distintas formas de organizar `N` computadoras, utilizando alguno de los casos de los siguientes sistemas operativos:
- Sistema operativos de red 
- Sistema operativo distribuido 
- Sistema operativo multiprocesamiento

## Aspectos de diseño en un sistema distribuido 

**Transparencia (latencia):**
- Es una característica de los sistemas distribuidos para ocultar al usuario la manera en que el sistema funciona o está construido.
- De tal forma, que el usuario tenga la sensación de que todo el sistema esta trabajando en una máquina local.

**Localización:**
- Los usuarios no pueden saber dónde se encuentran los datos localizados.

**Migración:**
- Los recursos se pueden mover a voluntad sin cambiar su nombre, es decir, se puede cambiar el alojamiento de éstos.

**Replica:**
- Los usuarios no pueden ver el número de copias existentes.

**Concurrencia:**
- Varios usuarios pueden compartir recursos de manera automática.

**Paralelismo:**
- La actividad o consulta puede requerir procesamiento paralelo sin que el usuario lo perciba.

**Fallas:**
- Para el usuario las fallas (Soft/Ward) deben ser imperceptibles.

**Desempeño:**
- El funcionamiento y velocidad de las máquinas donde se consulta el imperceptible para el usuario

**Escalabilidad:**
- El usuario ignora cuando en el sistema se agrega otra computadora.

**Flexibilidad:**
- Facilita modificaciones al diseño inicial (análisis de grafos -> reconfiguración del grafo inicial).

**Confiabilidad:**
- Permite que, en caso de que una computadora falle, otra la puede sustituir en la realización de sus tareas asignadas (redundancia)

**Desempeño:**
- Está en referencia a los tiempos de respuesta de la aplicación 

**Escalabilidad:**
- Permite que la arquitectura actual se le pueda adicionar más poder de cómputo.

**Repartición de carga:**
- Se analiza con qué equipos cuenta el sistema y los diferentes recursos de cómputo de cada uno de ellos.
	
- Recursos (procesado, memoria, disco duro)
	
- Funciones del sistema distribuido
	- Aplicaciones que van a utilizarse en el sistema distribuido 
	- Infraestructura de red
	
- Los tipos de arquitectura pueden ser:
	- Servidores - estación de trabajo
	- Pila de procesado
	- Multiprocesadores con memoria compartida 
	- Multiprocesadores con memoria distribuida

**Mantenimiento de consistencia:**
- Verificar que todos los elementos y conceptos de S.O operen de la forma correcta, como:
	- Modificaciones en el SO
	- Caché
	- Fallas
	- Replicación 
	- Interfaz de usuario
	- Reloj

**Funcionalidad:**
- Implica que el sistema distribuido funcione de acuerdo a las metas trazadas y eficientar el trabajo.
